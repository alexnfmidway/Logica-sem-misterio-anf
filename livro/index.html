CAPÍTULO 01 · PARTE I

Lógica de programação: pensar antes de codificar

Programar é dar instruções claras para resolver um problema. Antes do computador, existe o raciocínio.

Algoritmo é uma receita

Uma receita organiza ingredientes e passos para chegar a um resultado. Um algoritmo faz o mesmo: recebe informações, segue instruções e produz uma resposta.

🥪
Exemplo do dia a dia

Para montar um sanduíche: pegar o pão → passar o recheio → fechar → servir. Se a ordem muda, o resultado também pode mudar.

O caminho de uma solução

ENTRADAIngredientespão + queijo
↓
PROCESSAMENTOSeguir os passosmontar o sanduíche
↓
SAÍDAResultadolanche pronto
Por enquanto: vamos nos concentrar em entender o problema e descrever passos claros. Variáveis e tipos de dados serão estudados com mais cuidado no capítulo 3.
CAPÍTULO 02 · PARTE I

Resolver problemas em etapas

Antes de escrever instruções, precisamos entender o que é pedido, quais dados temos e como reconhecer uma solução correta.

Uma pergunta bem definida

Uma pessoa quer saber quantos minutos há em uma quantidade de horas. Em vez de começar pelo código, esclarecemos a tarefa.

  • Entrada: quantidade de horas.
  • Processamento: horas multiplicadas por 60.
  • Saída: quantidade equivalente de minutos.

Da pergunta ao resultado

DADO2 horas
→
REGRA2 × 60
→
RESPOSTA120 min
EtapaValorO que acontece
1. Ler2 horasRecebemos o dado.
2. Calcular2 × 60 = 120Aplicamos a regra.
3. Responder120 minutosApresentamos o resultado.
Uma solução em passos (pseudocódigo)IDEIA
leia horas
minutos ← horas × 60
mostre minutos

Pseudocódigo é uma forma informal e organizada de descrever a lógica sem depender da sintaxe de uma linguagem específica.

Pratique: descreva entrada, processamento e saída para calcular o total de uma compra com três produtos. Ainda não precisa escrever C#.
CAPÍTULO 03 · PARTE I

Memória, variáveis, constantes e tipos

Agora que sabemos descrever uma solução, vamos conhecer os dados que o programa guarda enquanto trabalha.

🧺
Imagine caixas identificadas

Cada caixa tem um nome e guarda um valor. Se o valor pode mudar durante o programa, usamos uma variável; para um valor que não deve mudar, podemos usar uma constante.

NOMES E VALORES NA MEMÓRIA
nome"Ana"texto · string
idade16inteiro · int
aprovadotruelógico · bool
▣

Variável

Um nome associado a um valor que pode ser atualizado, como a pontuação de um jogo.

#

Constante

Um nome associado a um valor que o programa não deve alterar, como os minutos de uma hora.

Aa

Tipo

Define quais valores fazem sentido: texto, número inteiro, número decimal ou verdadeiro/falso.

Os mesmos dados em C#C#
string nome = "Ana";
int idade = 16;
bool aprovado = true;
const int minutosPorHora = 60;

O tipo é declarado junto ao nome. A palavra const indica que o valor não será reatribuído.

Atenção: o sinal = em uma atribuição significa “guarde o valor da direita na variável da esquerda”. Não é uma pergunta de igualdade.
CAPÍTULO 04 · PARTE II

Entrada, processamento e saída

Todo programa interativo precisa receber dados, trabalhar com eles e comunicar um resultado.

Um programa como uma transformação

ENTRADAPreço e quantidadedados recebidos
→
PROCESSAMENTOPreço × quantidaderegra aplicada
→
SAÍDATotal da compraresposta mostrada

Exemplo: total de uma compra

Se cada caderno custa R$ 12,50 e a pessoa compra 3, o programa calcula 12,50 × 3 e mostra R$ 37,50.

Rastreamento: preço = 12,50 → quantidade = 3 → total = 37,50.

Uma versão em C#C#
Console.Write("Preço unitário: ");
decimal preco = Convert.ToDecimal(Console.ReadLine());
Console.Write("Quantidade: ");
int quantidade = Convert.ToInt32(Console.ReadLine());
decimal total = preco * quantidade;
Console.WriteLine($"Total: R$ {total:F2}");
Prática guiada: troque quantidade por 5. Antes de executar, preveja a saída; depois confira seu raciocínio.
CAPÍTULO 05 · PARTE II

Sequência de execução e operadores

Na estrutura sequencial, cada instrução acontece em ordem. Operadores permitem calcular, comparar e combinar condições.

Uma compra no mercado

Você pega dois produtos e calcula o total. Primeiro lê os preços, depois soma e, por fim, mostra o resultado.

  1. 1 Ler os preços
  2. 2 Somar os valores
  3. 3 Exibir o total
MERCADINHO DA ESQUINA
🍎 MaçãsR$ 5,00
🥛 LeiteR$ 6,50
TOTALR$ 11,50
5,00 + 6,50 = 11,50
Aritméticos

+ somar · - subtrair · * multiplicar · / dividir · % resto

Comparação

== igual · != diferente · > maior · < menor · >= maior ou igual

Lógicos

&& E · || OU · ! NÃO

Traduzindo a sequênciaC#
decimal macas = 5.00m;
decimal leite = 6.50m;
decimal total = macas + leite;
Console.WriteLine($"Total: R$ {total:F2}");

No código, = significa “guarde este valor”. Já == pergunta “estes valores são iguais?”.

CAPÍTULO 06 · PARTE II

Expressões e precedência de operadores

Uma expressão combina valores e operadores. A ordem das operações pode mudar o resultado, então precisamos torná-la explícita.

Qual conta acontece primeiro?

Considere 2 + 3 × 4. A multiplicação acontece antes da soma, então o resultado é 14. Com parênteses, (2 + 3) × 4 resulta em 20.

🧮
Uma regra útil

Use parênteses quando quiser destacar a intenção do cálculo, mesmo que a precedência já seja conhecida.

PassoExpressão
12 + 3 × 4
22 + 12
314
Deixe a intenção visível em C#C#
int resultadoPadrao = 2 + 3 * 4;     // 14
int resultadoAgrupado = (2 + 3) * 4; // 20

Em C#, multiplicação e divisão precedem adição e subtração. Parênteses agrupam a parte que deve ser calculada primeiro.

Desafio: sem executar, calcule 18 / 3 + 2 * 5. Depois acrescente parênteses para obter 40.
CAPÍTULO 07 · PARTE III

Tomando decisões com o programa

Uma condição permite escolher o que fazer. É como verificar uma regra antes de agir.

Você vai sair
↓
Está
chovendo?
SIMLevar guarda-chuva ☂️
NÃOSair sem guarda-chuva ☀️

Se isso, faça aquilo

A condição é uma pergunta que pode ser respondida com verdadeiro ou falso. O programa escolhe o caminho correspondente.

Decisão em C#C#
bool estaChovendo = true;
if (estaChovendo)
{
    Console.WriteLine("Levar guarda-chuva");
}
else
{
    Console.WriteLine("Pode sair!");
}

Com estaChovendo = true, a saída é “Levar guarda-chuva”. Se o valor for false, a saída é “Pode sair!”.

EXPERIMENTE

O ingresso tem desconto?

Considere que pessoas com até 12 anos pagam meia-entrada.

A pessoa paga meia-entrada 🎟️
Mais de duas opções? Use else if (senão, se) para testar outra condição; use switch quando há várias alternativas de um mesmo valor, como os dias da semana.
CAPÍTULO 08 · PARTE III

Decisões múltiplas e validações

Problemas reais costumam ter mais de dois caminhos. Podemos encadear regras e combinar condições sem deixar ambiguidades.

Classificar uma nota

Uma nota válida vai de 0 a 10. Abaixo de 0 ou acima de 10 é uma entrada inválida; dentro da faixa, podemos classificar o resultado.

Nota recebida
↓
Está entre
0 e 10?
SIMClassificar
NÃOMostrar erro
Validar e decidir em C#C#
double nota = 8.5;
if (nota < 0 || nota > 10)
{
    Console.WriteLine("Nota inválida");
}
else if (nota >= 7)
{
    Console.WriteLine("Aprovado");
}
else
{
    Console.WriteLine("Precisa recuperar");
}

|| significa OU. A validação vem primeiro para não classificar um valor fora da faixa. Com nota 8,5, a saída é “Aprovado”.

Pense: para permitir acesso somente quando a senha está correta e a conta está ativa, qual operador lógico combina as duas condições?
CAPÍTULO 09 · PARTE IV

Repetir enquanto uma condição for verdadeira

Laços condicionais são úteis quando a quantidade de repetições depende de uma situação que pode mudar.

Continuar até terminar

Imagine acompanhar uma conta até o saldo atingir zero. Antes de cada repetição, verificamos se ainda há saldo. É importante garantir que o valor mude para o laço terminar.

saldo = 30↶retirar 10↶saldo = 0
Condição verificada antes de repetirC#
int saldo = 30;
while (saldo > 0)
{
    saldo -= 10;
    Console.WriteLine(saldo);
}

A saída é 20, 10 e 0. O while pode não executar nenhuma vez se a condição começar falsa.

Verificação depois da primeira tentativaC#
int tentativa = 0;
do
{
    tentativa++;
    Console.WriteLine($"Tentativa {tentativa}");
} while (tentativa < 3);

Esse do...while executa três vezes. A condição só é verificada depois de cada execução.

CAPÍTULO 10 · PARTE IV

Para, contadores e acumuladores

Quando sabemos quantas repetições serão necessárias, o laço for organiza início, condição e atualização do contador.

Regar várias plantas

Em vez de escrever “regar a planta” dez vezes, podemos repetir a instrução enquanto houver plantas sem água.

🪴🌱🌿🪴🌱
regar uma↶próxima planta↶até acabar
Repetição com limiteC#
for (int planta = 1; planta <= 5; planta++)
{
    Console.WriteLine($"Reguei a planta {planta}");
}

O for é útil quando sabemos quantas vezes repetir. A saída lista “Reguei a planta 1” até “Reguei a planta 5”. O while repete enquanto uma condição for verdadeira.

⚠

Evite o laço infinito: confira se alguma coisa muda para que a condição deixe de ser verdadeira. Sem isso, o programa pode repetir para sempre.

Um acumulador dentro do laçoC#
int soma = 0;
for (int numero = 1; numero <= 5; numero++)
{
    soma += numero;
}
Console.WriteLine(soma); // 15

O contador numero avança a cada volta; o acumulador soma guarda o total parcial.

CAPÍTULO 11 · PARTE V

Vetores, percorrimento e pesquisa

Um vetor guarda vários valores do mesmo tipo. Podemos percorrer suas posições para calcular resultados ou procurar um item.

Vetor é uma fileira de gavetas

Um vetor guarda vários valores do mesmo tipo. Cada posição tem um índice. Em C#, a primeira posição é a 0.

notas
índice 08
índice 17
índice 29
índice 36

Índice é o endereço

Em C#, o primeiro índice é 0. Para um vetor com quatro valores, as posições vão de 0 a 3; tentar acessar 4 ultrapassa os limites.

índice → valor
08
17
29
36
Guardar e acessar notasC#
int[] notas = { 8, 7, 9, 6 };
int soma = 0;
for (int indice = 0; indice < notas.Length; indice++)
{
    soma += notas[indice];
}
Console.WriteLine(soma); // 30

Atenção: acessar uma posição fora do tamanho da lista causa erro. Neste exemplo, os índices das notas vão de 0 a 3.

Pesquisa linear: para encontrar a nota 9, percorra os valores da esquerda para a direita e compare cada posição com o valor procurado. A pesquisa termina quando encontra ou quando acaba o vetor.
SUA VEZ

Qual é a média da turma?

Informe três notas de 0 a 10. O programa vai guardá-las como uma coleção e calcular a média.

A média é 8,00.
CAPÍTULO 12 · PARTE V

Matrizes: dados em linhas e colunas

Quando uma coleção precisa de duas coordenadas, como uma tabela de assentos ou notas por pessoa e disciplina, uma matriz pode ajudar.

Uma tabela tem dois índices

O primeiro indica a linha e o segundo indica a coluna. Como nos vetores, em C# os índices começam em zero.

Col. 0Col. 1Col. 2 Fila 0123 Fila 1456
Percorrer linhas e colunasC#
int[,] lugares = { { 1, 2, 3 }, { 4, 5, 6 } };
for (int linha = 0; linha < 2; linha++)
{
    for (int coluna = 0; coluna < 3; coluna++)
    {
        Console.Write(lugares[linha, coluna] + " ");
    }
    Console.WriteLine();
}

A saída contém duas linhas: 1 2 3 e 4 5 6.

ValorLinhaColuna
612
Confira: qual valor está em lugares[0, 2]? Leia primeiro a linha 0 e depois a coluna 2.

Funções, procedimentos, parâmetros e retornos

Um programa grande fica mais fácil de entender quando separamos tarefas em partes menores e damos um nome a cada uma.

🎂Organizar uma festa
🎈Decorar
🍰Preparar comida
✉️Convidar

Uma função tem uma responsabilidade

Assim como cada pessoa pode cuidar de uma parte da festa, cada função resolve uma tarefa específica. Ela pode receber dados e devolver um resultado.

Por que isso ajuda?
O código fica mais legível, partes podem ser reutilizadas e fica mais simples encontrar onde corrigir um problema.
Uma função que calculaC#
static double CalcularMedia(double nota1, double nota2)
{
    return (nota1 + nota2) / 2;
}

double media = CalcularMedia(8, 10);
Console.WriteLine(media); // 9

CalcularMedia recebe duas notas (parâmetros), faz o cálculo e devolve a média com return.

Decomposição de problemas e modularização

Defina entradas e responsabilidades

Comece identificando o resultado esperado. Depois, divida a solução em tarefas que possam ser explicadas e testadas separadamente.

Uma decomposição possívelIDEIA
saldo = somar(receitas) - somar(despesas)

Modularizar é separar partes do programa em funções ou módulos com nomes e objetivos claros. Isso facilita compreender, reutilizar e testar a solução.
CAPÍTULO 15 · PARTE VI

Testes, depuração e erros comuns

Testar é verificar se a solução atende ao esperado. Depurar é investigar a execução para encontrar a origem de um problema.

Escolha casos que desafiem a regra

Para uma média de duas notas de 0 a 10, não teste apenas valores comuns. Experimente limites e entradas inválidas.

  • Valores comuns: 8 e 6 → média 7.
  • Limites: 0 e 10 → média 5.
  • Entrada inválida: uma nota negativa → rejeitar ou sinalizar.
EntradaEsperado
8, 67
0, 105
-1, 7Inválido
🔎
Uma sequência para depurar

Reproduza o erro → confira os dados de entrada → acompanhe os valores passo a passo → compare o resultado real com o esperado → corrija e teste novamente.

Erros comuns: condição que nunca termina, índice fora do vetor, divisão por zero, precedência esquecida e valores não validados. Um teste pequeno e bem escolhido ajuda a localizar cada tipo de falha.
CAPÍTULO 16 · PARTE VII

Do algoritmo para um programa C#

A lógica descreve a solução; C# fornece regras concretas para escrever um programa que o computador possa executar.

Mesma ideia, duas representações

Vamos calcular a média de três notas. Primeiro descrevemos os passos; depois expressamos a mesma solução em C#.

AlgoritmoPASSOS
ler três notas
somar as notas
dividir a soma por 3
mostrar a média
Implementação executável em C#C#
double nota1 = 8;
double nota2 = 7;
double nota3 = 9;
double media = (nota1 + nota2 + nota3) / 3;
Console.WriteLine($"Média: {media:F1}");

Com esses valores, a saída é Média: 8,0 em uma configuração regional que usa vírgula decimal.

O que mudou? As instruções informais viraram declarações, expressões e uma chamada a Console.WriteLine. O raciocínio permaneceu o mesmo.
Prática: altere os valores das notas, preveja a saída e confira. Depois, pense em que validações seriam necessárias para aceitar notas digitadas por uma pessoa.
CAPÍTULO 17 · PARTE VII

Projeto final: resumo de orçamento mensal

Vamos juntar entradas, operações, decisões, repetições e funções em uma aplicação de console pequena e útil.

O problema

Receber valores de receitas e despesas, calcular os totais e informar se o mês terminou com saldo positivo, zero ou negativo.

  • Dados: valores de receitas e despesas.
  • Processamento: somas e diferença entre totais.
  • Decisão: classificar o saldo.
  • Saída: resumo legível para a pessoa.

Como as partes trabalham juntas

Receitas→Somar→Saldo←Despesas
Uma primeira versão em C#C#
decimal[] receitas = { 3200m, 450m };
decimal[] despesas = { 1200m, 680m, 300m };

decimal totalReceitas = Somar(receitas);
decimal totalDespesas = Somar(despesas);
decimal saldo = totalReceitas - totalDespesas;
string situacao;
if (saldo > 0)
{
    situacao = "positivo";
}
else if (saldo < 0)
{
    situacao = "negativo";
}
else
{
    situacao = "zerado";
}

Console.WriteLine($"Receitas: R$ {totalReceitas:F2}");
Console.WriteLine($"Despesas: R$ {totalDespesas:F2}");
Console.WriteLine($"Saldo {situacao}: R$ {saldo:F2}");

static decimal Somar(decimal[] valores)
{
    decimal total = 0;
    for (int indice = 0; indice < valores.Length; indice++)
    {
        total += valores[indice];
    }
    return total;
}

Com os valores de exemplo, as receitas somam R$ 3.650,00, as despesas R$ 2.180,00 e o saldo é R$ 1.470,00 positivo.

Próxima evolução: valide os valores, permita mais lançamentos, extraia a classificação do saldo para uma função e crie casos de teste para saldo positivo, negativo e zero.
